## Session 002 — 2026-07-27

### What I accomplished
- Continued building a multi-step LLM workflow.
- Created a second prompt that adds documentation to the Python function generated by Prompt 1.
- Created a separate `documentation_messages` list for the second LLM request.
- Passed `generated_code` from Prompt 1 into Prompt 2 using an f-string.
- Reused the `generate_response()` helper function for a second LLM call.
- Reused `extract_python_code()` to remove commentary and Markdown formatting from the documented response.
- Stored the extracted result in a new variable called `documented_code`.
- Increased `max_tokens` from 1024 to 2048 so Gemini could return the complete documented function.
- Successfully generated and extracted a fully documented version of the even-or-odd function.

### What I learned
- Each step in a multi-prompt workflow can use its own messages list.
- The output from one LLM prompt can become the input for another prompt.
- An f-string is required when inserting the value of a variable into a larger string.
- Without the `f`, `{generated_code}` would be sent as literal text instead of the generated Python code.
- Helper functions such as `generate_response()` and `extract_python_code()` can be reused across multiple stages of an application.
- `documentation_response` contains the model's full response, including explanations and Markdown.
- `documented_code` contains only the Python code extracted from that response.
- `max_tokens` limits the number of tokens the model can generate, not the number of characters.
- A response that ends in the middle of a sentence can indicate that the output token limit was reached.
- Changing a function definition in an earlier notebook cell requires rerunning that cell before later cells can use the updated version.
- Prompt wording affects how much the model changes the original code. Asking the model to “improve” a function may cause it to change the implementation in addition to adding documentation.

### Challenges I solved
- Understood the difference between the system and user messages in Prompt 2.
- Learned why Prompt 2 needs a different messages list from Prompt 1.
- Diagnosed a Gemini `503 Service Unavailable` response as a temporary model-capacity issue rather than an error in the Python code.
- Investigated why the documented function was repeatedly cut off in the middle of its output.
- Confirmed that both `documentation_response` and `documented_code` were incomplete because the original LLM response had been truncated.
- Increased `max_tokens` from 1024 to 2048 and successfully received the complete response.
- Verified that `extract_python_code()` correctly removed the explanation and Markdown code fences.
